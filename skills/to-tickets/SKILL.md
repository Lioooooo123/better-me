# 计划拆解

复用已确认目标、方案与范围。按可交付行为拆分纵向任务，每项说明目的、必要上下文、完成标准与真实依赖；避免只按文件层次拆成无法独立验证的碎片。

跨全仓的机械重构若无法逐片保持可用，采用“增加兼容形式 → 分批迁移调用方 → 移除旧形式”。每批依赖兼容层，移除任务依赖全部迁移完成；只有确实无法单独通过验证时才约定共同集成分支与最终验收任务，不假称每批都能独立交付。

数量和格式服从计划复杂度。能在一个任务完成的工作不强拆；不强制 ready-for-agent 等标签体系。

只要求拆解时先给清晰任务清单。用户已要求发布时核对目标仓库或清单、现有任务和可用标签，避免重复创建；只有关键范围或目标未定时才提问，不重新询问已批准计划。

发布外部任务沿用当前会话的明确授权。关联创建结果的真实 ID/链接，报告部分失败，重试前判断是否已经创建。

联动：未定方案先用 `think`；飞书目标使用 `lark` 的任务模块；GitHub 用已可用 CLI/API。把计划和验收标准传给下一阶段，不再次触发规划循环。
