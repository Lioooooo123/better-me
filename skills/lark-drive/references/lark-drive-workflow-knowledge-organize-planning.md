# 整理计划

把分类转为可核对的源位置→目标位置与动作；保留真实资源 ID、类型、源父级、目标父级、理由和未确定项。小任务不需要专门 JSON 模型，大批量可保存清单便于续跑。

## 依赖与边界

- 复用已有目标容器；同名多个候选不能靠名字选择第一项。
- 新目标从浅到深创建，保存返回 token 后才安排依赖移动。
- 父节点与全部后代去同一目标子树时只移动父节点；后代有不同去向时先移这些后代，再移父节点，源深度从深到浅。
- 目标父级必须解析到 token；路径仅用于展示，不能传给移动命令。
- 比较父级类型、token 与 Wiki space_id 判断是否已在目标位置；明确 root 与未知父级不能都用空字符串混同。
- 待判定资源、空的旧目录默认保持原位置，不为清空根目录自动创建“待清理”路径或搬移它们。
- 写前记录原位置和原 token；Drive root / Wiki space root 是有效原位置，Wiki 根保留 space_id。无法确定原位置时说明恢复限制，不假造数据。

展示足够判断的目标树、动作数量、例外和具体移动明细；大清单用可打开的文件或按需分页。分页只影响展示，不偷偷把执行范围缩到当前页。

用户修正计划后，更新受影响项与依赖，执行当前有效计划；用户未要求只做修正项时保留原任务剩余范围。相同目标和影响的具体会话授权不失效，不要求复述或指定固定确认短语。新发现的目标歧义或实质权限继承变化需要说明并澄清；只请求方案时不执行。
