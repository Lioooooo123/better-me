# 写作

区分起草、改写、翻译与审稿。起草根据用户已给的要点完成；只有改写所需原文确实缺失时才索要原文。受众、语气和长度可以从上下文推断时直接采用。

保留事实、数字、专名、承诺和作者意图；不为更好听而增加成果。改写优先处理结构与具体表达，不机械替换词汇或标点。只读审稿给发现，已要求改写则形成成稿或实际文件 diff。

通常交付正文即可；只有事实缺口、实质改动或使用限制值得说明时才补一句。正常简历中的姓名、任职时间和求职信息不构成停工理由，按其交付对象处理具体隐私问题。

按需参考：

- 长文重组、压缩与论证：[长文](references/long-form.md)。
- 中英翻译、双语术语或产品本地化：[翻译与本地化](references/localization.md)。
- 批量文件需要统一字符级标点时，可运行 `bash scripts/check-punctuation.sh --lang zh <file>` 或 `--lang en`；短消息直接校对，不为了仪式调用脚本。脚本结果结合引文、用户格式和语言判断，不盲目替换。

联动：缺事实时使用 `read`/`learn`；求职定位用 `asu-skills`；生成简历文件用 `html-resume-builder`。用户要求发布到飞书时，把确认后的成稿交给 `lark-doc` 或 `lark-im`；起草授权本身不等于发送授权。
