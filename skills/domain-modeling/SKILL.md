# 领域语言

先找项目 AGENTS.md 指定的词汇表、领域文档或代码契约，再从现有用法和用户业务描述辨别歧义。

区分同义词、同名异义、实体与值、状态与事件。为真正影响交流或实现的概念记录定义、边界及一个能区分误用的例子；不要为所有代码类型创建词条。

标明不同上下文中同一个词的不同含义，以及转换由哪个边界负责。复杂命名选择根据业务而非技术框架决定。

已授权维护文档时更新现有规范位置；仅讨论时给出拟议定义。项目没有约定且确有持久化需求时才选择一个简洁词汇表，不自动另建 CONTEXT.md 与现有文档竞争。

记录 ADR 优先选择有真实取舍、反转成本较高或脱离背景容易被误改的决定。沿用项目格式；没有格式时，一段写清背景、决定和理由即可，不必填满模板。

决定及理由适合 ADR，稳定词义适合 glossary，临时排查结果留任务记录。不要把私人记忆当成新的项目规则。

联动：将明确术语交给 `think` 或 `codebase-design` 使用；无需每次再次确认已经解决的命名。
