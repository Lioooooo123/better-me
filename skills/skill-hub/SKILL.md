# 个人 Skill Hub

从当前目标与已有成果选择下一步需要的能力。小任务直接做；只有独立阶段确实需要专业方法时才加载相应技能，阶段完成后继续原任务。

## 选用路径

| 目标 | 按需要组合 |
|---|---|
| 实现功能 | `think` 解决未定方案；正常编码直接完成，明确要求测试优先时用 `tdd`；`check` 审查有风险的改动 |
| 排查故障 | `hunt` 定位与修复；需要模块调整时用 `codebase-design`；`check` 检查受影响路径 |
| 产品界面 | `ui` 实现或视觉修复；iOS 平台体验用 `ios-hig-design`；实际 Figma 转换才使用已安装 Figma 插件 |
| 研究并整理 | `read` 获取资料；`learn` 综合证据；需要成文用 `write`，明确保存笔记时用 `obsidian-vault` |
| 简历与求职 | `asu-skills` 提炼真实经历；`write` 润色；`html-resume-builder` 制作 HTML/PDF |
| 飞书工作 | `lark-doc` 管内容，`lark-drive` 找文件，`lark-wiki` 管知识结构；消息、日历、任务各用对应技能 |
| 工作交接 | 用户要求交接时用 `handoff`；要求计划变任务时用 `to-tickets` |
| Agent 环境维护 | `health` 审计配置或技能问题；实际技能编写使用系统 `skill-creator` |

## 联动方式

沿用同一任务中的目标、范围、已确认决定、来源/文件和验证结果。进入另一技能前，只补充它缺少的输入；不要让用户再次填写已有信息。

多步骤任务可以用几句工作记录传递“要交付什么、已有何证据、产物在哪里、下一步做什么”。无需为简单串联创建状态文件、JSON 协议、子任务或新会话。

伙伴技能只处理自己的阶段并返回产物；不再次调用 Hub，也不自动加载全部伙伴。上一步未确定的事实保持未确定，不能在写作或发布阶段变成已证实结论。

阅读、起草与发布是不同动作。只有用户已授权相应外部动作时才发送消息、发布内容或创建外部任务；传递既有授权，不增加新权限。

某个伙伴未安装时，若已有工具可完成该阶段就继续；只有确实缺能力时说明缺口。不要为了跑完整条路径自动安装插件或恢复已精简的飞书技能。
