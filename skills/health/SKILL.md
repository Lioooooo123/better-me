# Agent 环境审计

按用户指定对象检查 skills、指令、安装、工具或验证。先用当前文件和可重复的只读证据建立基线；历史对话与其他项目仅在用户要求或明确相关时读取。

对 better-me，在仓库运行 `python3 scripts/manage.py status` 检查链接与已安装集合，运行 `python3 scripts/validate.py` 检查源码结构与引用。用户要求核对上游时运行 `python3 scripts/check_upstream.py`；它只报告仓库分支是否变化，不能据此断言某个技能有更新，继续按 `catalog/upstream-state.json` 的目录与树指纹比较。执行位置应从安装链接或用户给出的仓库解析，不能假定当前目录就是 better-me。

其他项目依次检查：实际生效的指令来源、相互冲突的条款、技能触发与依赖、已知失败对应的验证能力。文件大、工具多、没有某种模板都只是线索，不能单独判坏。

按用户指定范围处理个人源码、系统技能或插件；仅要求优化个人技能时，不修改系统技能或插件缓存。区分缓存、显式调用与当前目录列出的技能。记录来源、内容版本和维护归属，检查实际断链和不适用的工具名。只在依赖可用性影响当前目标时运行无副作用探针，不普遍调用所有外部服务。

报告每个问题的层级、准确证据、实际影响及具体下一步。模式扫描命中要阅读上下文，不能把安全说明里的示例当成攻击。

普通审计不修改安装或配置；会话已授权优化时才形成修复和回归检查。不要自动更改权限、MCP、记忆或其他运行时配置。

联动：源码变更审查用 `check`；具体工具故障用 `hunt`；修技能时用系统 `skill-creator`。返回证据与修改范围，不再启动另一轮通用审计。
