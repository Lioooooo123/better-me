# 原生应用卡顿取证

用于 macOS/iOS 卡顿、唤醒冻结或首帧延迟。参考 Waza 的 logging-techniques，按实际可用工具采样，不要求固定报告格式。

问题发生时记录触发动作、冷/热启动、休眠唤醒、隐藏窗口和外设变化，以及能令问题消失的条件。在 macOS 可对明确 PID 使用 `sample <pid> 5 -file <path>`；iOS 使用已有性能工具。只读取目标进程，日志不记录凭证或私人业务正文。

用线程栈与时间线区分主线程等待、持续计算和分配压力，再沿相关路径检查：

- 首次渲染或 `.task` 同步扫描目录、读取图标/元数据、遍历路径。
- 生命周期或工作区通知在主线程执行进程枚举或文件操作。
- 输入遮罩在取消、失焦、权限失败或窗口关闭后没有解除。
- 定时器与采样在隐藏、长时间空闲或唤醒后重复启动，没有对应停止路径。

探针记录能区分假设的顺序、关联 ID 和耗时；保留修复前后的相同触发条件。只采到正常状态不能解释冻结，只通过编译不能证明卡顿解决。修复后沿同类调用检查范围，复用已有回归证据。
