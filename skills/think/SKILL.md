# 方案与决策

先确认要改善的结果、现有约束和成功标准。优先读取项目约定、现有实现与已作决定；只研究会影响决策的未知项。

提出足够区分的可行选择，说明每个选择在实际场景中的收益、成本和迁移影响。若存在明显合适的方案，直接推荐，不为凑选项发明替代方案。

把推荐方案落实为必要的边界、数据流、修改范围与验证办法。步骤粒度应足以开始执行，不要求固定数量、固定文档格式或每一步再审批。

明确讨论请求停在方案交付；用户已要求实施时继续完成授权范围中的实现。缺少会改变方案的关键业务事实才提问；常规实现选择可说明假设后决定。

联动：术语存在实际分歧时用 `domain-modeling`；模块边界是核心问题时用 `codebase-design`。研究材料沿用 `read`/`learn` 的已有来源，不重新抓取。只有用户要求拆成外部任务时才用 `to-tickets`。
