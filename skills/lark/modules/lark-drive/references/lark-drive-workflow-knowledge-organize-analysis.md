# 整理内容分析

以 [盘点](lark-drive-workflow-knowledge-organize-discovery.md) 的真实资源与路径为基础。标题、路径与类型已经足够分类时直接使用；证据不足时按 [docs fetch](../../lark-doc/references/lark-doc-fetch.md) 获取大纲、主题命中段或相关 section，避免默认全文读取。确需全文才能满足用户目标时可读取，不设三次后机械停止的流程。

表格、Base 等内容只能通过 [对应可选服务](../../lark-shared/references/optional-services.md) 获取；不能用 docx 接口替代。

可检查根目录堆积、同类分散、命名不一致、疑似临时资源、空目录、重复目录和旧资源位置；每项附数量或真实样例路径。“test”或旧日期只是分类线索，不是可以删除的证据。

分类原则：

- 复用清晰的现有结构与用户约定，不强加二级/三级树、数值前缀或通用类别。
- 按实际项目、客户、业务线、年份或文件类型归类，每个新类别有资源证据。
- 内容不清、无权限、读取失败的资源记为待判定并保留原位置；用户指定临时目录时才纳入该移动计划。
- 分类建议和将执行动作分别记录，用户修订分类后更新受影响计划，保留其余原请求。
- 未授权删除、改名或权限治理不因发现问题而执行；需要这些操作时通过原子命令处理相应明确请求。

只读分析与 [计划生成](lark-drive-workflow-knowledge-organize-planning.md) 可以连续完成，无需先让用户审批整理思路。大量数据按需分批并报告实际进展，不要求固定页数或输出模板。
