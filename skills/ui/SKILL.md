# 产品界面

先检查现有设计系统、同类组件、真实数据字段与目标截图。成熟产品沿用其样式与交互，新增页面不默认重新建立品牌或设计语言。

明确此次要改变的可观察问题：层级、密度、对齐、响应式、状态、反馈或可访问性。根据已有输入决定方向；真正缺少会改变结果的偏好才提问，沉默不能替代必要输入或授权。

实现使用项目当前框架与组件方式，避免因个人审美更换工具链。真实接口数据、加载、空、错误和内容极值都应有合适表现；演示数据只能在允许的原型中清楚标识。

颜色、字体、卡片和动画按产品方向选择，不使用全场景禁令。动效服务操作反馈并尊重减少动态效果设置；不强制每个按钮位移。

截图修复把看到的差异先归为几项具体问题，再定位对应组件或样式；每次修订比较同一宽度和同一状态。若没有原截图、真实数据或登录态，准确标明比较范围，避免凭新截图猜测原问题已经解决。

验证受影响的界面状态、目标宽度及键盘/辅助功能行为。尽可能用真实运行截图检查具体差异；没有运行或只看到未登录页时明确视觉验证缺口。

交付可运行修改及实际验证。只有用户要求或跨页面协作确实需要时才新增设计文档，不为普通修复输出品牌论文。

联动：iOS 原生体验使用 `ios-hig-design`；已有 Figma 输入且需转换时使用对应 Figma 插件；视觉探索或 UX 流程审计可用已安装 Product Design；图片资产使用当前图像工具。文档、简历和 PDF 不转介到未请求的设计产品。
