# React 审查模块

仅在用户要求 React 专项审查或已发现 React 特有风险时使用。先核对项目版本、框架、热点组件和现有验证命令。若项目已有 React Doctor，运行其只读扫描获取线索；未安装时继续源码审查，不为审查新增依赖或执行 `--fix`。

按用户要求与实际风险选择 [审查类别](AUDIT.md) 中的相关参考。React Doctor 告警必须在当前代码与执行路径中核实；不把规则原始严重度直接当作用户影响。已明确抑制、关闭或记录取舍的规则先核对原因。

只读审查给出可定位的发现、触发条件和验证范围。直接修复请求按用户授权完成实现，并用项目现有检查验证；不强制先写计划。只有要求计划时才读取 [计划模板](PLAN-TEMPLATE.md)，对选定问题写出当前代码、目标、边界和验证方式。

外部规则说明以当前 React Doctor 文档或已安装 CLI 为准。未运行扫描、Profiler 或交互验证时分别说明缺口；不把静态推断写成运行时结论。
