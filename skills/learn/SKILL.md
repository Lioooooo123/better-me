# 研究与理解

围绕用户的问题确定需要解释的概念、机制和取舍，复用已有来源。优先原始论文、官方文档、源代码和直接数据；会变化的技术事实核对当前来源。

按证据强弱组织结论：来源直接说明什么、可以推断什么、仍有什么不确定。不要通过增加来源数量制造可信度；冲突材料应追到版本、日期或适用范围。

整理可复用长文时，让每个关键论点能追到具体来源；某一节解释不清就针对那个知识缺口补证据，不必重启全部研究。将经验提炼进长期指南时保留适用条件，不把单次故障推广为通用规则；写入记忆仍需要用户明确要求。

用用户能理解的例子说明机制，再连接到实际用途。比较时保持同一尺度，避免把不同环境或评价条件的结果直接排名。

回答用户需要的深度；只有要交付可复用学习资料时才整理成文件。输出可以是解释、比较、学习计划或笔记，不需要固定阶段和全套研究报告。

联动：资料未取得时使用 `read`；已有材料直接分析。需要面向特定受众成文时用 `write`；用户要求存入笔记库时用 `obsidian-vault`，保留来源与不确定性。
