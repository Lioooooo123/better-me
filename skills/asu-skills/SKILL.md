# 求职叙事

从目标岗位与真实经历中找对应关系：解决了什么问题、用户本人做了什么、为何这样做、结果有什么证据。工程代码和实际职责优先于漂亮称谓。

区分本人实现、团队成果、参与协作和仅了解的部分。不把接入工具写成设计底层，不把调用模型写成训练模型，不把构想写成上线效果。

数字使用可证明的来源；没有数据就用范围清楚的定性结果，不补造效率、用户量或营收。材料不足时先给有依据的草稿与少量重要缺口。

按请求交付单条亮点、自我介绍、HR 消息或完整简历内容，不默认扩成全套求职包。长案例与面试准备只在需要时读 [表达方法](references/career-framing.md)。

联动：`write` 调整语言，`html-resume-builder` 排版导出。向下游传递事实与个人贡献边界，不能在润色阶段升级成未证实的能力。
